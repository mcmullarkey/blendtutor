# ADR-0016: Browser BYOK storage, provider, and auto-mount decisions

- Status: Accepted
- Date: 2026-08-07

## Context

The Quarto extension's BYOK feedback path (byok-api-key AC-1..AC-7) settled a
bundle of decisions that supersede earlier records. Storage moved from
`sessionStorage` to `localStorage`; the learner-facing provider became
Fireworks-only with a pinned model; feedback became auto-mounted (reversing
the filter-runtime-bootstrap "manual opt-in" decision); and an API key page
was added. This ADR records the settled end-state and the supersession chain
so a reader never trusts the stale claims in ADR-0009/ADR-0014. The historical
ADRs are not rewritten — only their status lines are annotated.

## Options

1. **Amend ADR-0014 in place.** Update its storage claims and title. Rejected:
   ADR-0014's title ("shared sessionStorage") and body would contradict the
   record's own history; a new ADR preserves the decision timeline.
2. **New ADR-0016 + status annotations on ADR-0009/ADR-0014.** Record the new
   decisions in a fresh ADR and annotate the superseded ADRs' status lines
   ("superseded by ADR-0016") without rewriting their bodies. Chosen.

## Decision

- **Storage: `localStorage`, not `sessionStorage` (supersedes ADR-0014).** The
  BYOK key persists in `localStorage` as a raw string and is shared across
  pages of the same origin. Unlike `sessionStorage` (tab-scoped, gone on tab
  close), `localStorage` survives navigation across pages — required for a
  multi-page book where the key is entered once. Supersedes ADR-0014's
  provider-scoped `sessionStorage` slots claim (ADR-0014 title, :29-33, :46).
- **Fireworks-only learner UX (partially supersedes ADR-0009).** Browser BYOK
  targets Fireworks AI only, using the pinned model
  `accounts/fireworks/models/deepseek-v4-flash-0731`; the extension ships no
  Anthropic option. The multi-provider chooser and `sessionStorage` key-slot
  claims in ADR-0009 (:79-87, :99-102) are stale for the extension. The CLI
  `run`/`eval` path is unaffected (ADR-0006, rig).
- **Auto-mounted feedback (reverses the filter-runtime-bootstrap manual
  opt-in decision).** The injected bootstrap auto-mounts per-exercise feedback
  (`mountAllFeedback` after `start()` resolves) and the API key page
  (`mountKeyPage`). Pages opt out granularly with `bt-feedback: false`, or
  entirely with `bt-auto-bootstrap: false`.
- **Key page.** A dedicated API key page (e.g. `api-key.html`) is auto-mounted
  via `__btConfig.keyPageUrl`; the key is entered once there and reused across
  exercises.
- **Security model (browser-direct).** The key is stored as a raw string in
  `localStorage` — readable by any JavaScript on the page's origin, so an XSS
  vulnerability can steal it. Mitigations shipped: no third-party scripts,
  textContent-only rendering, and the key is sent only in the `Authorization`
  header to `api.fireworks.ai` (host-gated `providerBaseUrl`). This is an
  inherent client-side-key tradeoff, not a vault; users are advised not to
  reuse critical keys. Fireworks CORS is open to GitHub Pages origins
  (`Access-Control-Allow-Origin: *`, verified empirically), so the
  browser-direct call works from Pages without a proxy.
- **file:// limitation.** `file://` breaks `localStorage` sharing across pages
  AND blocks ES modules; books must be served over HTTP.
- **CSP recommendation (not enforced).** For self-hosted deployments we
  recommend adding `connect-src https://api.fireworks.ai` to the
  Content-Security-Policy. GitHub Pages cannot set CSP headers, and the
  `coi-serviceworker` shim covers only COOP/COEP — it is not a CSP mechanism.

## Consequences

- Supersedes ADR-0014's storage claims and partially supersedes ADR-0009
  (:79-87 multi-provider chooser, :99-102 `sessionStorage` key slots).
  ADR-0009's host-gate security invariant and ADR-0014's
  per-exercise-container architecture remain valid.
- `docs/okf/interfaces/js-runtime-seam.md:57` still documents `sessionStorage`
  for the crates-built site path (`crates/core/assets/shared/feedback.js`),
  which is a different subject — that file is generated by the okf-bundle
  skill; regenerate it after the crates path migrates, do not hand-edit.
- `docs/agent-notes/feedback.md` gains an extension-divergence note
  (localStorage, Fireworks-only, auto-mount) while the crates claims stay
  intact.
- `.opencode/plans/filter-runtime-bootstrap.md` auto-mount-OUT boundary note is
  annotated SUPERSEDED in place.
