## Decision Log

- **Circular import safe**: exercise-feedback.js → key-page.js is a cycle
  (key-page.js already imports the storage/provider contract FROM
  exercise-feedback.js). Both use imported bindings only at call time; no
  module-eval-time use. Browser + Node ESM both fine.
- **onSaved fires after storeKey, before advisory validation resolves**:
  optimistic contract — key stored = proceed. A rejected/unreachable
  validation is advisory copy only; continuation is not blocked. Empty save
  and storage-unavailable save never fire onSaved (contract pinned by P17).
- **keyPageUrl() retained**: api-key.qmd chapter + lua keyPageUrl emission +
  index.qmd link stay (secondary entry); only the no-key branch no longer
  renders the link. key-page-url.test.js unchanged.
- **CSS flatten**: `.bt-feedback [data-byok="key-page-form"]` override added in
  crates source (sync-scoped to `.bt-exercise .bt-feedback ...` — beats the
  :global passthrough by specificity, so no card-in-card inline).
- **WeakSet idempotency**: one mount per container → one submit listener →
  one save → one onSaved. After save the container is replaced by
  pending/verdict, so a second save is impossible in the real DOM.

- The crates styles.css SOURCE differs from the scoped _extensions copy
  (sync script prefixes .bt-exercise except :global passthrough) — dead
  no-key rules must be removed from the crates source, and the flatten
  override must be added there too, then `sync-quarto-assets.sh` regenerates.
- demo-book/_extensions/mcmullarkey/blendtutor/assets/* are vendored copies:
  byte-identical to _extensions/blendtutor/assets/* (verified with cmp) — JS
  edited in _extensions then cp'd; styles.css regenerated by sync then cp'd.
- The key-page form's Save button dispatches a submit event on the FORM, not
  the button — Node mock tests must call `form._handlers.submit[0]` (or
  `_listeners.submit[0]`) with a preventDefault stub.
- renderPending (onSaved continuation) replaces the form BEFORE the advisory
  validation fetch resolves, so the "saved" status line is never visible in
  the inline flow — the observable contract is: key stored → one feedback
  fetch → verdict. Probe asserts verdict, not the transient status line.
